1. **Репозиторий.** Вся разработка ведётся ТОЛЬКО в этом GitHub-репозитории, созданном

   вне репозитория команды).
2. **Подтверждённый результат на каждый отчётный час.** По Положению отсутствие у команды
   подтверждённого промежуточного результата по итогам ЛЮБОГО отчётного часа соревновательной
   части — самостоятельное основание для дисквалификации. Практически это значит: **каждый час
   должен быть реальный коммит** (код и/или `docs/progress.md`) в этот репозиторий. Это не
   формальность для судей — это защита от дисквалификации. См. `docs/progress.md`.
3. **Воспроизводимость.** Технические эксперты должны суметь самостоятельно развернуть, запустить
   и проверить проект по инструкциям из этого README — без вопросов к команде и без ручных
   правок. Несоответствие этому требованию может быть основанием для недопуска к дальнейшему
   отбору (см. Положение, раздел о технической экспертизе). Проверяйте это на «чистом»
   клоне репозитория, а не в среде, где что-то уже настроено руками.
4. **Внешние сервисы / API.** Если решение использует внешний API или сервис (в первую очередь —
   OpenAI API), команда обязана обеспечить техническим экспертам демо/тестовый доступ, не
   требующий личных аккаунтов участников. См. раздел «Демо/тестовый доступ» ниже и
   `docs/resources-needed.md`.
5. **Заранее подготовленная инфраструктура — не финальный продукт.** Часть файлов в этом
   репозитории (этот README, `CLAUDE.md`/`AGENTS.md`, скрипт-хук `.claude/hooks/`,
   `.claude/settings.json`, `.claude/agents/supervisor.md`, шаблоны `docs/*.md`) подготовлена
   заранее, до объявления кейса. Это допустимо — Положение прямо разрешает заранее готовить
   инфраструктуру, инструменты и шаблоны при условии, что они не являются готовым продуктом
   и не составляют основную (профильную) часть решаемой задачи. Основной функционал,
   специфичный для выбранной задачи, разработан в течение соревновательной части — это
   зафиксировано по часам в `docs/progress.md`.

## Что реализовано

### Backend B1–B3 (ветка `backend`)

Реализованы проверка входов, подготовка истории через Data D1, эмпирическая кривая мощности
каждой турбины и HTTP API. Python 3.11+, сторонние зависимости не нужны.
Из чистого клона этой ветки:

```bash
git clone --branch backend https://github.com/BAITC-Hacks/hack-8df1dc64-inc.git
cd hack-8df1dc64-inc
python -m unittest discover -s backend/tests -t . -v
python -m backend.server
```

Инструкции запросов, настройки архива и ограничения — в [backend/README.md](backend/README.md).
История организаторов включена в ветку; API работает на 127.0.0.1:8000. Для прогноза нужен
реальный архивный погодный пакет. Его автоматическое получение, OpenAI-цикл и подключение
UI ещё не завершены. Ключ OpenAI для текущих B1–B3 не требуется. Разделы-шаблоны ниже
сохраняются для последующего заполнения общей командой.
