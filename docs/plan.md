# План реализации Ветропрогноза

Полный текст ТЗ и таблица технической оценки (25/25/25/15/10) находятся в task-board.md. Номер кейса в полученном тексте не указан.

## Реализованные этапы

1. B1: контракт, 24–48 часов, строгая почасовая сетка, issued_at ≤ available_at ≤ as_of.
2. D1/B2: реальные CSV, контрольные суммы, GMT+5, почасовая агрегация с явным start/end, историческая кривая по каждой турбине.
3. B3: HTTP API, ошибки, CORS, два ручных входа и тесты.
4. D2: 30 архивных погодных пакетов NOAA с provenance, 28 запусков покрывают февраль.
5. B4: реальный анализ OpenAI Responses API, ключ только на сервере.
6. B5: автоматическое получение/обновление NOAA, ограниченный цикл анализа и пересчёта, подключение UI Богдана, график/таблица/CSV, февральский численный прогон.

## Демо

31 января 19:00 UTC / 24 ч / обе турбины → расчёт → график и CSV → анализ и ограничения → другой срез 14 февраля / 48 ч / турбина 2 → обновление NOAA. Агент проверяет новый архив, повторно рассчитывает изменённые входы, не придумывает обновление.

## Границы MVP

Нормализованная мощность, исторические запуски и JSON/CSV без отдельного сервера БД. Нет подтверждённой точности февраля, поскольку целевые значения не предоставлены. Смысл временных меток и высота исторического ветра остаются неизвестными. Улучшение модели и проверка качества требуют дополнительных данных; их нельзя подменять успешными тестами API.
