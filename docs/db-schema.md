# Схема данных

Источник истины по структурам data → backend. Версия B1 согласована пользователем
2026-09-23 до реализации кода. Хранение в базе данных на этом этапе не требуется.

## Источники и известные ограничения

Полный текст ТЗ находится в `docs/task-board.md`. История ВЭС ещё не получена.
Источник архивных прогнозов погоды пока не выбран. Нельзя подменять архивные прогнозы
фактической погодой или переанализом. Синтетические данные разрешены только для тестов правил.

Входы B1 используют согласованные ниже имена; преобразование исходных столбцов — задача
адаптера data после осмотра реального файла. Часовой пояс истории, единицы и шкала мощности,
а также трактовка её часовой метки пока неизвестны и не предполагаются автоматически.

## Время и числовые значения

Входная дата: `YYYY-MM-DDTHH:MM:SS[.ffffff]Z` или то же со смещением `±HH:MM`.
Даты без часового пояса не допускаются. Сравнение и результат — UTC.
`as_of` и `valid_at` должны попадать на целый час UTC. Времена выпуска и публикации
могут содержать минуты и секунды. Невозможные даты и смещения отклоняются.

Числа — Python `int`/`float`, кроме `bool`, конечные и представимые конечным `float`.
Числовые строки не преобразуются автоматически. Все строки должны содержать непробельный текст.

## ForecastRequest

| Поле | Тип | Правило |
|---|---|---|
| `as_of` | datetime string | Момент запуска исторического прогноза, целый час UTC |
| `horizon_hours` | integer | 24–48 включительно; `bool` и дробные числа запрещены |
| `turbine_ids` | array of string | Непустой список известных ID без повторов |

Пример:

```json
{
  "as_of": "2026-01-31T19:00:00Z",
  "horizon_hours": 24,
  "turbine_ids": ["turbine_1", "turbine_2"]
}
```

Сетка: `as_of + 1 час`, ..., `as_of + horizon_hours часов` для каждой выбранной турбины.
Метка обозначает конец интервала. Это соглашение внутреннего формата B1, а не утверждение
о разметке ещё не полученных данных организатора. При необходимости адаптации сначала
обновляется контракт.

## WeatherBatch

| Поле | Тип | Правило |
|---|---|---|
| `source` | string | Идентификатор погодного источника |
| `run_id` | string | Идентификатор одного выпуска |
| `issued_at` | datetime string | Время выпуска модели |
| `available_at` | datetime string | Время доступности выпуска в источнике |
| `availability_evidence` | string | Ссылка или описание основания для времени доступности |
| `wind_height_m` | number | Высота ветра, метры, строго больше нуля |
| `points` | array of WeatherPoint | Полная сетка запроса, без дублей и лишних точек |

Обязательный порядок: `issued_at <= available_at <= as_of`.
Время загрузки архива сегодня не является временем исторической доступности.
Backend проверяет порядок времён и наличие описания основания; достоверность этого основания
обеспечивает выбранный источник и адаптер data. Проверка не подтверждает подлинность архива.
Все точки одного пакета относятся к одному выпуску. Смешивание выпусков требует отдельного
расширения контракта.

## WeatherPoint

| Поле | Тип | Правило |
|---|---|---|
| `turbine_id` | string | Одна из турбин запроса |
| `valid_at` | datetime string | Конец прогнозируемого часа, принадлежит сетке запроса |
| `wind_speed_ms` | number | Скорость ветра в м/с, >= 0 |
| `temperature_c` | number | Температура в °C, конечное число |

Одна точка (не полный погодный пакет):

```json
{
  "turbine_id": "turbine_1",
  "valid_at": "2026-01-31T20:00:00Z",
  "wind_speed_ms": 7.5,
  "temperature_c": -3.0
}
```

Ни одно обязательное поле не принимает `null`. Неизвестные поля отклоняются.
Формат исторических наблюдений и результата прогноза мощности будет согласован отдельно
после получения реальных данных; B1 не задаёт диапазон нормализованной мощности.
