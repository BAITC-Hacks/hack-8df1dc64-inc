Источник истины по структурам data → backend. Версия B1 согласована пользователем
2026-09-23 до реализации кода. Хранение в базе данных на этом этапе не требуется.

## Источники и известные ограничения

Полный текст ТЗ находится в `docs/task-board.md`. История ВЭС получена 2026-09-23: два CSV,
фактический период 2023-03-11 — 2026-01-31. Февральских наблюдений в них нет.
Источник архивных прогнозов погоды пока не выбран. Нельзя подменять архивные прогнозы
фактической погодой или переанализом. Синтетические данные разрешены только для тестов правил.

Входы B1 используют согласованные ниже имена; преобразование исходных столбцов — задача
адаптера data после осмотра реального файла. GMT+5 истории подтверждён пользователем.
База нормализации мощности и смысл метки интервала пока неизвестны; детали D1 — ниже.

## Время и числовые значения

Входная дата: `YYYY-MM-DDTHH:MM:SS[.ffffff]Z` или то же со смещением `±HH:MM`.
Даты без часового пояса не допускаются. Сравнение и результат — UTC.
`as_of` и `valid_at` должны попадать на целый час UTC. Времена выпуска и публикации
могут содержать минуты и секунды. Невозможные даты и смещения отклоняются.

Числа — Python `int`/`float`, кроме `bool`, конечные и представимые конечным `float`.
Числовые строки не преобразуются автоматически. Все строки должны содержать непробельный текст.

## ForecastRequest

| Поле | Тип | Правило |
|---|---|---|
| `as_of` | datetime string | Момент запуска исторического прогноза, целый час UTC |
| `horizon_hours` | integer | 24–48 включительно; `bool` и дробные числа запрещены |
| `turbine_ids` | array of string | Непустой список известных ID без повторов |

Пример:

```json
{
  "as_of": "2026-01-31T19:00:00Z",
  "horizon_hours": 24,
  "turbine_ids": ["turbine_1", "turbine_2"]
}
```

Сетка: `as_of + 1 час`, ..., `as_of + horizon_hours часов` для каждой выбранной турбины.
Метка обозначает конец интервала. Это соглашение внутреннего формата B1, а не утверждение
о разметке ещё не полученных данных организатора. При необходимости адаптации сначала
обновляется контракт.

## WeatherBatch

| Поле | Тип | Правило |
|---|---|---|
| `source` | string | Идентификатор погодного источника |
| `run_id` | string | Идентификатор одного выпуска |
| `issued_at` | datetime string | Время выпуска модели |
| `available_at` | datetime string | Время доступности выпуска в источнике |
| `availability_evidence` | string | Ссылка или описание основания для времени доступности |
| `wind_height_m` | number | Высота ветра, метры, строго больше нуля |
| `points` | array of WeatherPoint | Полная сетка запроса, без дублей и лишних точек |

Обязательный порядок: `issued_at <= available_at <= as_of`.
Время загрузки архива сегодня не является временем исторической доступности.
Backend проверяет порядок времён и наличие описания основания; достоверность этого основания
обеспечивает выбранный источник и адаптер data. Проверка не подтверждает подлинность архива.
Все точки одного пакета относятся к одному выпуску. Смешивание выпусков требует отдельного
расширения контракта.

## WeatherPoint

| Поле | Тип | Правило |
|---|---|---|
| `turbine_id` | string | Одна из турбин запроса |
| `valid_at` | datetime string | Конец прогнозируемого часа, принадлежит сетке запроса |
| `wind_speed_ms` | number | Скорость ветра в м/с, >= 0 |
| `temperature_c` | number | Температура в °C, конечное число |

Одна точка (не полный погодный пакет):

```json
{
  "turbine_id": "turbine_1",
  "valid_at": "2026-01-31T20:00:00Z",
  "wind_speed_ms": 7.5,
  "temperature_c": -3.0
}
```

Ни одно обязательное поле не принимает `null`. Неизвестные поля отклоняются.
B1 не принимает исторические наблюдения; экспорт истории Data описан в D1 ниже.
Формат результата прогноза мощности согласуется отдельно; B1 не задаёт диапазон мощности.

## D1 — подготовка исторических наблюдений в Data

Дополнение Data от 2026-09-23, записано до реализации адаптера по запросу пользователя
обработать два переданных CSV. B1 и его погодные пакеты не изменяются; история не является
архивным прогнозом погоды. Подключение истории к модели backend — следующий этап команды.

Источник: `data/raw/turbine_1.csv.gz`, `data/raw/turbine_2.csv.gz` — побайтово сохранённые
CSV организаторов после распаковки gzip. Исходные имена и SHA-256 — в `data/raw/manifest.json`.
Пользователь подтвердил **фиксированный GMT+5** для времени источника. Не подставлять
исторические правила зоны Asia/Almaty вместо этого подтверждённого фиксированного смещения.

`data.history.iter_observations(path, turbine_id)` читает источник, преобразует числа и
возвращает наблюдения: `turbine_id`, `source_id`, `source_time` (исходный текст),
`timestamp` (datetime UTC), `wind_speed_ms`, `normalized_power`, `temperature_c`.
Соответствия: `ID` → source_id; `Статистическое время` → timestamp;
`Средняя скорость ветра(m/s)` → wind_speed_ms; `Нормализованная активная мощность`
→ normalized_power; `Средняя температура окружающей среды(°C)` → temperature_c.
Исходники имеют шаг 10 минут с разрывами. Пустые/нечисловые значения, NaN/inf,
дубли ID/времени, неверные колонки и нарушение порядка отклоняются; данные не исправляются
молча. Мощность сохраняется в исходной нормализованной шкале; в кВт/кВт·ч не переводится.

`data.history.hourly_history(observations, as_of, timestamp_role)` возвращает
`{"points": [...], "excluded_incomplete_hours": N, "excluded_after_cutoff": N,
"excluded_test_rows": N}`. `as_of` — datetime с поясом на целом часе, сравнение в UTC.
`timestamp_role` обязательно задаётся явно: `start` — исходная метка начала 10 минут,
`end` — конца. Это пока не подтверждённая характеристика источника; нельзя выбирать
вариант автоматически. При `start` конец интервала = метка + 10 минут.

Точка: `turbine_id`, `valid_at` (ISO 8601 UTC с Z, конец часа), `wind_speed_ms`,
`temperature_c`, `normalized_power`, `sample_count` (=6). Час соответствует интервалу
`(valid_at - 1 час, valid_at]` по концам исходных 10-минутных интервалов.
Среднее арифметическое шести измерений вычисляется только для полного часа (концы
на минутах 10,20,30,40,50,60); пропуски не интерполируются, неполный час исключается.
Показатели мощности здесь означают среднюю нормализованную мощность, не энергию.
Конец каждого использованного интервала <= as_of. Записи с исходной датой >= 2026-02-01
не попадают в историю обучения даже при более позднем as_of. Тестовые наблюдения
не подменяют отсутствующие прогнозы. Пустая доступная история — ошибка.
