# Внешние ресурсы, необходимые решению

Заполняется на Шаге 2 плана (`docs/plan.md`), сразу после определения идеи решения. Не
изобретать источник, если не уверены — использовать плейсхолдер `[НУЖНО НАЙТИ: тип источника]`
и рассмотреть переход на синтетические/тестовые данные как fallback.

Если решение использует внешний API/сервис — по Положению команда обязана обеспечить
техническим экспертам демо/тестовый доступ к нему, не требующий личных аккаунтов участников
(колонка «Демо-доступ для экспертов» ниже — обязательна к заполнению до сдачи).

| Что | Зачем в пайплайне | Статус доступа | Fallback | Демо-доступ для экспертов (обязательно) |
|---|---|---|---|---|
| OpenAI API | Оркестрация модели — обязательная техническая часть решения (agentic AI, технологический партнёр хакатона) | [заполнить: ключ выдан / логистика уточняется] | — | [заполнить: как эксперт проверит без своего ключа] |
| История двух турбин ВЭС | Подготовка истории для расчёта | Получены CSV от пользователя; 291859 строк, 2023-03-11 — 2026-01-31, GMT+5 подтверждён | Синтетика только в тестах | Исходники gzip и контрольные суммы в data/raw; личный аккаунт не нужен |
| Архив выданных погодных прогнозов | Исторический прогноз февраля без утечки будущего | [НУЖНО НАЙТИ: подтверждённые архивные выпуски с временем публикации] | Не заменять реанализом или фактической погодой | Требуется подтвердить источник и доступ |
| Фактическая выработка февраля 2026 | Проверка точности на тестовом месяце | В полученных CSV отсутствует, несмотря на имена файлов | Не генерировать целевые значения | Нужен отдельный файл организаторов |

## Примечание по OpenAI API

То, что продукт технически вызывает OpenAI API — не обсуждается, это дано по формату хакатона.
Единственное, что может быть неопределённым на старте — логистика выдачи/лимитов ключа
конкретной команде на площадке; это вопрос организационный, не архитектурный, и не должен
влиять на дизайн решения в `docs/architecture.md`.
