## Регулярный порядок для каждого агента

Проверять Git перед каждой задачей, перед коммитом/пушем и каждые 10–15 минут активной
длительной работы. Эти действия выполняет работающий агент; отдельный фоновый процесс
обновления файлов не настроен.

1. Проверить `git status --short --branch`, чтобы видеть ветку и незакоммиченные изменения.
2. Выполнить `git fetch origin`: получить опубликованные коммиты всех веток без изменения
   рабочих файлов.
3. Посмотреть `git log --all --oneline --decorate -12`. Для новых коммитов соседнего модуля
   прочитать `git show origin/data:docs/task-board.md` и
   `git show origin/data:docs/progress.md`, заменив `data` нужной веткой.
   Аналогично просмотреть изменения контрактов и файлов, от которых зависит своя задача.
4. При чистом рабочем дереве выполнить `git pull --ff-only origin <своя-ветка>`.
   При наличии своих правок сначала ограничиться `fetch` и просмотром удалённых версий.
   Не затирать файлы ради получения обновлений.
5. Если поменялись общие документы `main`, получить их по инструкции ниже после коммита
   своей работы. `fetch` и обновление своей ветки сами по себе не объединяют разные ветки.
6. Указать в своём прогрессе значимые обнаруженные изменения и зависимости: новый контракт,
   готовый эндпоинт, данные или блокирующее условие. Не переписывать чужие отчёты.

При ошибке, расхождении истории или конфликте остановиться и показать проблему пользователю.
Force-push, `reset --hard` и автоматическое затирание незакоммиченных изменений для этого
процесса не применяются. Код соседних модулей остаётся в их ветках до согласованной интеграции.

## Получить общие документы

Из корня своего клона, находясь в своей рабочей ветке, после коммита локальной работы:

```bash
git fetch origin
git merge origin/main
```

Это добавляет изменения общей ветки в рабочую. `git pull` без указания ветки обновляет
только upstream текущей ветки и сам по себе не переносит новые документы из `main`.
Если Git сообщает конфликт, покажите различия команде до выбора версии; записи о работе
каждого участника нужно сохранить.
