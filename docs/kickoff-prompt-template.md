# Стартовые промпты для каждого участника

Скопировать нужный блок в свою свежую сессию Claude Code/Codex сразу после того, как
`docs/generator-prompt.md` уже прогнан и все файлы контракта заполнены реальным содержанием
кейса.

## Backend (+ API)

```
Прочитай CLAUDE.md (или AGENTS.md, если ты Codex) полностью — это контракт команды.
Прочитай docs/plan.md, docs/api-contract.md, docs/db-schema.md, docs/task-board.md.
Прочитай полный текст ТЗ задачи (раздел 1 CLAUDE.md/AGENTS.md) — критерии оценки именно этой
задачи важнее общих формулировок.

Ты работаешь в /backend. Твоя первая задача: [заполнить конкретную первую задачу].

Перед началом: проверь docs/task-board.md, добавь свою задачу туда со статусом in-progress.
После задачи: обнови свою строку в docs/progress.md за текущий час (что сделано + как работает
простыми словами) — сделай это сам, без напоминания, это требование протокола команды и
защита от риска дисквалификации по Положению (нет подтверждённого результата за отчётный час).
Обнови ./test.sh под новую функциональность и прогони его.
```

## Если присоединяешься к чужому модулю (handover)

Перед использованием любого из промптов выше — сначала прочитать `docs/handover-protocol.md`
и выполнить его шаги (проверить task-board, дождаться пуша от текущего владельца, сделать
`git pull` актуальной ветки). Только после этого использовать стартовый промпт нужного модуля,
но с уточнением в первой строке: «Присоединяюсь к модулю [X], уже есть код от [ИМЯ] — сначала
прочитай существующий код и docs/progress.md по этому модулю за предыдущие часы, не начинай
с нуля».
