# Архитектура

Заполняется сразу после Шага 0 плана (`docs/plan.md`) — то есть ПОСЛЕ прочтения полного ТЗ
выбранной задачи, не до. Архитектура должна отвечать требованиям именно этого ТЗ, а не общей
идее, которую команда обсуждала заранее.

## Общая схема (типовой agentic-пайплайн — адаптировать под задачу)

```
[Входные данные] → [Обработка / правила] → [Оркестрация вызовов OpenAI API] →
→ [Расчёт результата] → [API] → [UI]
```

1. **Входные данные** — [заполнить: тестовый датасет / открытые данные / ручной ввод —
   см. `docs/resources-needed.md`]
2. **Обработка / правила** — [заполнить: какая простая логика/валидация применяется до вызова
   модели]
3. **Оркестрация вызовов OpenAI API** — использование OpenAI API является обязательной
   технической частью решения (хакатон проводится при технологическом партнёрстве OpenAI,
   формат — agentic AI). [Заполнить: какие именно вызовы, с каким промптом/ролью модели]
4. **Расчёт результата** — [заполнить: как из ответа модели + данных получается финальный
   результат для пользователя]
5. **API** — [заполнить: см. `docs/api-contract.md`]
6. **UI** — [заполнить: как показываем результат]

## Важно: не переусложнять

- НЕ пытаться обучать собственную ML-модель — на это физически нет времени в 5-часовом окне.
  Используем простую математику/правила + вызовы OpenAI API.
- Предпочитать самый короткий путь от входных данных до работающего демо-сценария, а не самую
  «интересную» архитектуру.

## Внешние зависимости

Полный список внешних API/данных/сервисов и статус доступа к каждому — в
`docs/resources-needed.md`. Для каждого внешнего сервиса, использованного в решении, README
должен содержать способ демо/тестовой проверки без личного аккаунта участника — не забыть
перенести туда финальную версию.
