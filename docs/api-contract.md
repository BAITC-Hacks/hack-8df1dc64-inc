# API-контракт

Единственный источник истины о том, как `backend` (включая API) и `ui` договариваются между
собой. Контракт обязателен, даже если backend и API реализует один человек: `ui` разрабатывается
по контракту, не дожидаясь фактической готовности backend.

**Правило изменения:** обсудили → обновили этот файл → только потом меняем код. Не наоборот.

## Эндпоинты

| Метод | Путь | Кто вызывает | Кто реализует | Статус |
|---|---|---|---|---|
| POST | `/api/[заполнить]` | ui | backend | [не начато / в работе / готово] |

## Схема запроса/ответа

### `POST /api/[заполнить]`

Запрос:
```json
{
  "example_field": "string"
}
```

Ответ (200):
```json
{
  "example_field": "string"
}
```

## Ошибки

| Код | Когда | Тело ответа |
|---|---|---|
| 400 | [заполнить] | `{"error": "..."}` |
| 500 | [заполнить] | `{"error": "..."}` |

## Демо/тестовые данные для проверки контракта

Если `backend` вызывает внешний API (OpenAI и т.п.), указать здесь, как проверить эндпоинт без
реального внешнего вызова (например, фиксированный тестовый вход с детерминированным ответом) —
это упрощает независимую разработку `ui` и ускоряет `./test.sh` каждого модуля.
