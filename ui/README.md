# UI — Ветропрогноз

Ответственный за UI: **Богдан (22Malish22)**. Разработка при помощи Codex.

Экран прогнозирования ВЭС: выбор даты и целого часа запуска в UTC, одной или двух турбин,
горизонта 24/48 часов; сводка выбора и пустое состояние почасового результата.
Настройки сохраняются в браузере, восстанавливаются при открытии и сбрасываются кнопкой.
Русский интерфейс, адаптивная вёрстка и сообщения об ошибках рядом с полями.

## Текущая интеграция B5

По явному разрешению пользователя Codex (сессия smmaff) подключил UI Богдана к реальному API.
Полная инструкция запуска: [общий README](../README.md). Запустите Python backend на 8000 и UI на 3000.
Кнопка расчёта отправляет `POST /api/agent/forecasts`, показывает график/таблицу/CSV, анализ OpenAI
и реальные этапы. Кнопка обновления скачивает NOAA и повторяет расчёт. Выбор роли метки времени явный,
`end` остаётся допущением. Дизайн, иллюстрация и анимация Богдана сохранены.

26 автоматических тестов: `node --test ui/tests/ui.test.mjs ui/tests/draft.test.mjs ui/tests/design.test.mjs ui/tests/api.test.mjs`.
Реальная HTTP-проверка того же клиента: `node ui/smoke-api.mjs`; требуется настроенный backend и ключ.
С `LIVE_REFRESH=1` второй запрос заново загружает NOAA. Успешно проверены 24 часа/две турбины
и 48 часов/турбина 2 с настоящими ответами OpenAI. Браузерная визуальная приёмка ещё требуется.

## История этапов UI-01–UI-06

Описания ниже фиксируют прежние этапы до подключения API; ограничения про недоступный расчёт

## Запуск

Нужен Node.js 22 или новее. Сторонних зависимостей и шага сборки нет.
Из корня репозитория:

```sh
node ui/server.mjs
```

Открыть http://127.0.0.1:3000. Сервер раздаёт только статические файлы UI.
Порт можно поменять переменной окружения `PORT`.

## Проверки

```sh
./ui/test.sh
```

В Windows PowerShell без Bash:

```powershell
node --test ui/tests/ui.test.mjs ui/tests/draft.test.mjs ui/tests/design.test.mjs
```

Если Node отсутствует в PATH, укажите путь к исполняемому файлу в `NODE_BINARY` для test.sh
или запускайте node по полному пути. Тесты проверяют разные наборы параметров, границы дат,
часы UTC, выбор турбин, ошибки ввода, сохранение/восстановление/сброс и реальную HTTP-раздачу
страницы и её ресурсов. Отдельно проверены повреждённые настройки, запрет хранения и
исчерпание квоты. Адаптер Web Storage в тестах использует память; API не подменяется.

Ручная проверка:

1. Открыть страницу без ранее сохранённых настроек: выбраны 31 января 2026, 19:00 UTC,
   24 часа и две турбины. Сводка показывает этот выбор; результатов нет, запуск недоступен.
2. Выбрать 14 февраля 2026, 00:00 UTC, 48 часов и только турбину 2: сводка обновляется.
   Перезагрузить страницу — при доступном localStorage выбор восстанавливается.
3. Снять обе турбины или очистить дату: рядом с полем появляется ошибка, сводка скрывается.
   Предыдущий сохранённый выбор удаляется, чтобы после перезагрузки не возникали устаревшие параметры.
4. Нажать «Сбросить параметры»: устанавливается начальный выбор, сохранённая запись удаляется.
   Данные других приложений в localStorage не затрагиваются.
5. Проверить ширину 375 px и управление Tab / стрелками / пробелом: поля доступны,
   карточки расположены в одну колонку.

Хранится только ключ `wind-forecast.selection.v1` с параметрами формы; результатов, API-ключей
и данных истории в нём нет. Неверные или неизвестные версии записи не восстанавливаются.
При запрете Web Storage форма продолжает работать, а сообщение явно указывает, что сохранение
недоступно. Удаление записи при сбросе также проверяется; ошибка удаления не скрывается.

## Граница текущего этапа и подключение backend

После синхронизации с `main` (коммит `5e82b90`) в `docs/api-contract.md` находится
контракт B1: он задаёт внутреннюю Python-валидацию, а HTTP API и формат результата
прямо отмечены как несогласованные. Поэтому UI не отправляет запросы,
не рассчитывает выработку, не показывает придуманные значения или выполненные этапы агента.
Раздел цикла агента объясняет требования ТЗ и не является журналом выполнения.

Для следующего этапа необходим согласованный контракт: адрес backend, метод и путь,
формат даты и часовой пояс, поля запроса, почасового ответа и ошибок, способ получения
статуса и результата (если расчёт асинхронный). Дата и час сейчас — явный выбор пользователя
в UTC, без автоматического пересчёта часового пояса устройства. Начальное 19:00 взято из
примера ForecastRequest B1, это выбранный параметр, а не результат расчёта.
Начало прогнозного периода UI не вычисляет. Погодные источники, модели,
анализ и пересчёт остаются в backend. Ограничение дат в форме относится к экрану
исторического воспроизведения по ТЗ, а не к серверной валидации.

Ключи внешних сервисов для UI не нужны. Вклад Codex: экран, стили, обработка ввода,
локальная раздача статики и тесты созданы в этой сессии; исходный шаблон команды предшествовал ей.

## Результат проверки этапа UI-01

2026-09-23: все 6 тестов прошли через `ui/test.sh`, Node.js 22.16.0. Дополнительно вручную
проверены выводы функции отображения для 31 января / 24 ч, 14 февраля / 48 ч и пустой даты.
Ревью: нет запросов к выдуманному API, расчёта мощности или фиктивных результатов;
тексты вывода вставляются через `textContent`. Визуальная проверка в браузере и проверка
клавиатуры/мобильной ширины ещё не выполнены: инструмент управления вернул пустой список
доступных браузеров. Инструкция для этих проверок приведена выше.

## Проверка этапа UI-03

Проверены два конкретных набора: 31 января / 19:00 UTC / 24 ч / две турбины и
14 февраля / 00:00 UTC / 48 ч / турбина 2; при отсутствии турбин сводка не формируется.
Все 17 тестов прошли через обновлённый `ui/test.sh`; проверен синтаксис app.mjs и HTTP 200
обновлённой страницы и draft.mjs. Исполняемый код не содержит расчёта прогноза или временных
API-заглушек. Новые проверки используют те же функции формы и сохранения, что и приложение.
Визуальная приёмка и браузерная проверка обработчиков событий остаются невыполненными:
повторный запрос инструмента управления вернул пустой список браузеров.

## Оформление UI-04

Все 30 требований пользователя разобраны в [design-review.md](design-review.md).
Нейтральная серая палитра, прямые углы, Arial/Georgia, обычные разделители; без градиентов,
теней, декоративных значков, точечного фона и анимации. Формы и сохранение настроек работают
как прежде. В футере находятся условия локальной демоверсии и описание хранения данных.

При импорте приложения и восстановлении выбора показывается skeleton параметров.
Он связан с реальной загрузкой модулей, без таймера и выдуманного прогресса расчёта.
До готовности форма недоступна; при ошибке отображается просьба перезагрузить страницу.
Все 20 тестов прошли. Визуальная приёмка в браузере остаётся невыполненной.

При заключительном fetch UI-04 обнаружен `origin/backend a68a513`: там уже зафиксирован
HTTP-контракт B3, реализация ещё в работе. Это следующий этап интеграции UI-02;
в текущем интерфейсе HTTP-запросы прогноза пока не добавлены.

## Анимация UI-06

22Malish22 при помощи Codex: по запросу пользователя лопасти плавно вращаются вокруг
неподвижных осей, а короткие линии ветра движутся вправо и плавно исчезают перед повтором.
Холмы и башни неподвижны; скорость вращения декоративная и не изображает погодные данные.
Анимация на CSS включается только при `prefers-reduced-motion: no-preference`; с настройкой
уменьшения движения остаётся статичная иллюстрация. Дополнительных зависимостей нет.
22 теста прошли; проверены SVG XML, HTTP страницы/стилей и сводки двух наборов параметров.
Визуальная проверка движения в браузере ожидается: инструмент не обнаружил браузеров.
