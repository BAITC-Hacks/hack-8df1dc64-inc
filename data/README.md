# Data: история двух турбин ВЭС

Python 3.11+, только стандартная библиотека. Код Data читает и проверяет исходники,
готовит историю для модели; прогноз мощности и погодный агент относятся к backend.

## Быстрый запуск

Из корня репозитория:

```bash
./data/test.sh
python3 -m data.prepare_history audit
```

Для сохранения нового отчёта: `--output /tmp/source-audit-new.json`.
Файл назначения не должен уже существовать. Проверенный отчёт этого запуска:
`data/reports/source_audit.json`.

## Полученные данные

Оба CSV переданы пользователем 2026-09-23. В `data/raw/*.csv.gz` сохранены исходные
байты, сжатые gzip; скачивать файлы отдельно или иметь личный аккаунт не требуется.
Имена оригиналов, размеры, SHA-256 и основание часового пояса — `data/raw/manifest.json`.
Перед обработкой CLI проверяет контрольные суммы распакованных файлов.

| Источник | Строк | Пропущенных 10-минутных меток | Разрывов |
|---|---:|---:|---:|
| turbine_1 | 142360 | 9992 | 67 |
| turbine_2 | 149499 | 2853 | 178 |

Оба файла фактически покрывают 11.03.2023 00:00 — 31.01.2026 23:50.
В полном диапазоне ожидалось 152352 записи для каждой турбины. Пустых ячеек,
дублирующихся ID/дат, неверных чисел и нарушений порядка в полученных файлах не найдено.
Температура может быть отрицательной. Мощность в этих файлах находится в [0,1];
её физическая база нормализации неизвестна, значения не переводятся в кВт или кВт·ч.

**Февраля 2026 в данных нет**, несмотря на имена CSV. Эти файлы дают историю до тестового
месяца, но не фактические целевые значения для проверки точности февральского прогноза.
Самый длинный разрыв первой турбины — 5993 недостающих записи (около 42 дней).
Все границы разрывов и помесячные количества доступны в отчёте.

## Время и подготовка часов

Пользователь подтвердил фиксированный **GMT+5**. Конвертация использует это смещение
для всей истории, а не меняющиеся исторические правила Asia/Almaty.
Смысл метки (начало/конец 10-минутного интервала) пользователь подтвердить не смог.
Загрузчик сохраняет исходную строку времени; автоматического выбора роли нет.

Следующая команда — **пример сценария с допущением о начале интервала**, а не
подтверждение разметки организатора:

```bash
python3 -m data.prepare_history hourly \
  --as-of 2026-02-01T00:00:00+05:00 \
  --timestamp-role start \
  --output /tmp/history-start-new.json
```

Для варианта с концом интервала используйте `--timestamp-role end` и другой output.
Без роли метки CLI завершается ошибкой. Выбранная роль и
`timestamp_role_confirmed: false` сохраняются в результате. Уточнение роли необходимо
до использования такого результата в окончательном историческом расчёте.

Полный час содержит ровно шесть последовательных 10-минутных интервалов. Для ветра,
температуры и нормализованной мощности вычисляется среднее; час помечается временем
его окончания в UTC. Турбины не объединяются. Неполные часы исключаются, пропуски
не заполняются нулями или интерполяцией. Счётчик неполных часов относится к часам,
в которых было хотя бы одно доступное наблюдение; полностью пустые периоды видны в аудите.

Ни один использованный интервал не заканчивается позже `as_of`.
Строки с исходной датой начиная с 01.02.2026 исключаются из истории обучения даже
при более позднем `as_of`. Для каждого исторического запуска нужно заново задать cutoff;
результат для конца января нельзя использовать для более раннего запуска.
Время публикации измерений неизвестно: ограничение по концу интервала не доказывает
фактическую доступность телеметрии в тот момент.

Интерфейсы и поля описаны до реализации в `docs/db-schema.md`, раздел D1.
`data.history.iter_observations` поддерживает CSV и CSV.gz с колонками организатора.
`data.history.hourly_history` принимает наблюдения и явные настройки расчёта.
Существующий общий `data/audit_csv.py` остаётся для других CSV с произвольными колонками.

## Проверки

`./data/test.sh` проверяет исходные контрольные суммы и покрытие обоих реальных файлов,
GMT+5, оба варианта метки, средние значения, независимость турбин, пропущенные часы,
повторы, некорректные поля, запрет будущих/февральских строк и обязательность параметров.
Искусственные строки в unit-тестах отделены от реальных источников.
Исходники не исправляются и не перезаписываются. Для итогового артефакта CLI создаёт
новый файл, чтобы не затереть предыдущий расчёт.

## Остающиеся зависимости команды

- Уточнить начало/конец интервала и задержку доступности исторической телеметрии.
- Получить фактическую выработку февраля для проверки точности.
- Подтвердить источник архивных погодных выпусков и время их публикации.
  Наблюдаемая погода из этих CSV не заменяет прогнозы погоды, требуемые ТЗ.
- Подключить историю D1 к модели backend; B1 пока проверяет только погодный пакет.
