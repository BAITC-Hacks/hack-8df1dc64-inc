# D2: передача реальной погоды владельцам Backend/UI

Пользователь выбрал `timestamp_role=end` как неподтверждённое допущение.
В JSON запроса B3 передавать `end`; `timestamp_role_confirmed` остаётся false.

Data поставляет:
- `data/weather/*.json` — реальные пакеты WeatherBatch B1 (NOAA GFS);
- соседние `.provenance.json` — версия источника, байты и время публикации;
- `data.weather_gfs.build_archive(as_of, horizon_hours=48)` — автоматическая загрузка;
- `python -m data.prepare_weather ...` — CLI с возобновлением по готовым файлам;
- `python -m data.check_backend --output /tmp/check-new.json` — реальная HTTP-проверка.

В backend выставить `WEATHER_ARCHIVE_DIR` на абсолютный путь `data/weather`.
После получения ветки data существующий `/api/forecasts` читает файлы без изменения
кода модели. B3 проверен с backend f25ef67 в отдельной папке; 24 часа для одной
турбины, 48 для двух, затем 48 часов на февраль — HTTP 200.

Для agentic-сценария владельцу backend нужно вызвать `build_archive`, сохранить
пакет либо передать его как `weather`, затем использовать свой AgentService.
Data не редактировал backend и не запускал оплачиваемый OpenAI-анализ в этой проверке.
Обновление готового архива не должно затирать предыдущие свидетельства источника.

Сетка NOAA 0.5°, ближайший узел; обе турбины могут получить одинаковые погодные
значения. Ветер на 100 м, температура на 2 м. Высота исторического ветра неизвестна.
Из шагов через 3 часа вычисляются часовые приближения; см. db-schema D2.
Last-Modified подтверждает наличие нынешней версии объекта в публичном NOAA S3
до cutoff, но не является историческим журналом работы HTTP.

Проверенная точность базовой модели пока слабая: MAE 0.2674–0.3879 в исходной шкале
0–1 на двух январских окнах. На одном окне turbine_1 не лучше среднего истории.
Подробные значения и baseline — `backend_current_integration.json`.
Для честной оценки февраля нужны скрытые/отдельные факты организаторов.

Публикация Data выполняется в ветке data. main и соседние ветки не перезаписываются.
Рабочая папка этого участника без .git; файлы/refs проверяются и публикуются через
GitHub API с родителем текущей ветки и `force=false`.

Проверки D2: 41 тест Data в чистой экспортированной папке, 60 тестов Backend f25ef67,
все 28 погодных пакетов проверены B1. Покрытие: 2688 точек 48-часовых прогнозов;
1344 уникальных турбино-часа первых суток = 672 часа февраля × 2 турбины.
Ещё 2 пакета января сохранены для воспроизводимой проверки. Git clone на этом
компьютере недоступен; чистая папка собрана из проверенных файлов, это не заявляется
как выполненный финальный тест клонирования всей системы.
